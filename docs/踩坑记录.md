> 整理时间：2026-10-11 ｜ 持续更新

## 一、WSL2 安装与 VMware 共存

### 1. `wsl --install` 下载发行版报 `WININET_E_CANNOT_CONNECT`

- **原因**：微软 CDN 在国内连不上（WSL 本体已装好，只是发行版下不动）。
- **解法**：从国内镜像下载 `.wsl` 镜像，再手动导入：
  ```powershell
  wsl --import Ubuntu-24.04 E:\wsl\Ubuntu-24.04 .\ubuntu-24.04.5-wsl-amd64.wsl --version 2
  ```
- **镜像地址**：`https://mirrors.aliyun.com/ubuntu-releases/24.04/`（清华、中科大、华为云也有）。

### 2. 单线程下载只有几十 KB/s

- **原因**：镜像站对单连接限速。
- **解法**：分段多线程下载（8 连接并行，curl `-r start-end`），速度可提升 5~10 倍。

### 3. `wsl --import` 安装的发行版首次启动直接是 root

- **原因**：import 方式没有商店版的"创建用户"引导。
- **解法**：手动建用户并设为默认：
  ```bash
  adduser fanta && usermod -aG sudo fanta
  printf '[user]\ndefault=fanta\n' > /etc/wsl.conf
  # 然后 Windows 侧 wsl --shutdown 再进
  ```

### 4. WSL2 与 VMware 的 Hyper-V 冲突

- **根因**：CPU 的 VT-x 同一时刻只能被一个 Hypervisor 独占。
- **结论**：VMware Workstation 16.1+ 可以走 WHP 接口与 WSL2 共存，但**性能损失 8~15%**。
- **大坑**：开了 Hyper-V 后，VMware 虚拟机若勾选了「处理器 → 虚拟化 Intel VT-x/EPT」，**启动直接失败** —— 必须取消勾选。
- **建议**：VMware 17.x 起个人免费，对共存支持更成熟；macOS 虚拟机共存模式下无解。
- **兜底**：`toggle-hypervisor.bat`（管理员运行）可一键开关 Hyper-V，重启生效，操作完全可逆。

### 5. 每个 WSL 发行版必须单独一个目录

- 所有发行版的虚拟磁盘都叫 `ext4.vhdx`，同目录会互相覆盖。

## 二、网络与镜像

### 6. WSL 里 apt 只有 11k/s

- **排查顺序**：① Windows 代理（系统代理开关 / Clash 全局或 TUN 模式）→ ② IPv6 半残路由 → ③ 换镜像站。
- **测速命令**：
  ```bash
  curl -4 -o /dev/null --max-time 15 -r 0-10485759 -w "%{speed_download} B/s\n" https://mirrors.aliyun.com/ubuntu-releases/24.04/ubuntu-24.04.5-wsl-amd64.wsl
  ```
- **注意**：Ubuntu 24.04 的 apt 源是 **deb822 格式**，文件在 `/etc/apt/sources.list.d/ubuntu.sources`（不再是老的 sources.list）。

## 三、Python 环境与依赖

### 8. `uv: command not found` 但明明装过

- **原因**：pipx 把 uv 装在 `~/.local/bin/`，当前终端的 PATH 没加载。
- **解法**：`export PATH="$HOME/.local/bin:$PATH"`（新终端会自动生效）；或激活 venv 后 `pip install uv` 装进环境。

### 9. `uv pip install unsloth` 会顺手升级 torch

- **现象**：装 Unsloth 时 torch 从 2.5.1+cu124 被升到 2.14.1+cu130。
- **教训**：装新库后先看 `uv pip list | grep torch`；**能跑就不要乱动版本**，驱动支持就没问题。

### 10. WSL 里绝对不要装 Linux 版 NVIDIA 驱动

- Windows 驱动会自动透传进 WSL，装 Linux 驱动会直接搞坏 CUDA 通道。

### 11. 微调框架是"两条路线"，按需安装

- **LLaMA-Factory**：WebUI + 配置文件，不写代码。
- **Unsloth**：Python 库，手写脚本，速度快 2x、显存省一半（对 8GB 卡是刚需）。
- 两者共用底层（Transformers/PEFT/TRL/bitsandbytes），按脚本选一条装即可。

## 四、数据与模型（本次最大的坑）

### 12. ⭐ Git LFS 指针文件：clone 下来的数据集只有 133 字节

- **现象**：`datasets` 加载报 `JSON parse error: Invalid value. in row 0`。
- **原因**：仓库用 Git LFS 管理大文件，本机没装 git-lfs，clone 下来的只是"取货单"（指针），不是文件本体。**而且这次 clone 把昨天完好的 18MB 真文件覆盖了**。
- **识别方法**：`head -c 100 文件`，看到 `version https://git-lfs.github.com/spec/v1` 就是指针。
- **解法**：
  ```bash
  # 根治（以后 clone 自动拉真实文件）：
  sudo apt install -y git-lfs && git lfs install
  # 或直接下直链（ModelScope 支持 /resolve/ 路径）：
  curl -L -o 文件名 "https://www.modelscope.cn/datasets/<组织>/<仓库>/resolve/master/<路径>"
  ```
- **验证**：指针对比 sha256 与 size，或直接用 Python `json.load` 试读。
- **教训**：clone 数据集到**新目录**，永远不要覆盖已有文件。

### 13. 模型放 `/mnt/e`（Windows 盘）加载慢

- **原因**：跨文件系统是 9P 协议，读取约 150MB/s（ext4 内可到 1GB/s+）。
- **影响**：8.8GB 模型加载 1~2 分钟，可接受；但**数据集和 checkpoint 频繁读写一定要放 Linux 家目录**。
- **注意**：WSL 的 vhdx 在 E 盘，把文件挪进 `~/` 依然不占 C 盘。

## 五、训练与显存（8GB 生存指南）

### 14. WDDM 显存税

- Windows 显示驱动模型预留 8~15% 显存：8GB 卡实际可用 ~6.8GB，Windows 桌面还要再占 ~1.3GB。**规划模型规模按 85 折算**。
- `.wslconfig` 里 `guiApplications=false` 可省 300~500MB。

### 15. 8GB 跑 4B QLoRA 的必备组合拳

`load_in_4bit`（权重 4bit）+ `use_gradient_checkpointing="unsloth"`（30% 速度换一半显存）+ `batch=1, accum=8` + `optim="adamw_8bit"` + LoRA 只训 0.1% 参数。

- OOM 了先关 Windows 端吃显存的程序（浏览器硬件加速），再把 `MAX_SEQ_LEN` 从 2048 降到 1024。

### 16. NVIDIA 控制面板的隐藏杀手

「CUDA - Sysmem Fallback Policy」要设为 **Prefer No Sysmem Fallback**。否则显存爆了不报错，而是静默把张量倒到内存走 PCIe —— 速度掉 10 倍还找不到原因。

### 17. 健康训练的体征

- loss 从 ~2.0 起步稳步下降；出现 `nan` 或恒为 0 就是有问题。
- `nvidia-smi` 显存吃满 7~~7.8GB、GPU 利用率 95~~100% = 正常。
- 训练过程**不需要网络**，全部本地计算。
