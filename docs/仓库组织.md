# 仓库组织：代码 / 数据 / 权重 三仓分离

## 为什么分三个仓

| 东西 | 特征 | 放一个仓会怎样 |
|---|---|---|
| 代码 + 人设卡 + 场景库 | 文本，几 MB，频繁改 | — |
| 训练数据 + 评测报告 | 文本 json，2~3 MB，**含私人聊天内容** | 混在代码仓里，clone 代码就带出隐私 |
| adapter 权重 | **二进制 85MB/版** | git 每次都存完整快照，10 版就 850MB，**永久无法回收** |

**git 不适合存二进制。** 这是拆仓最硬的理由，不是洁癖。

## 三个仓各放什么

| 仓库 | 内容 | 可见性 | 体积 |
|---|---|---|---|
| `model_tuning` | 训练脚本、人设卡、场景库、`app/`、`docs/`、`eval_persona.py` | 可公开 | < 1 MB |
| `ev-data` | `my_data/*.json`、`eval_result_*.md`、README(provenance) | **必须私有** | ~1.5 MB |
| `ev-models` | `lora_adapter/`（每版 85MB）| **必须私有** | 85MB × 版本数 |

> 权重仓建议直接用 **ModelScope**（或 HuggingFace）而不是 git ——
> 它们原生支持大文件、断点续传、版本标签，且国内下载快。

## 目录布局（三仓平级）

```
~/repos/
├── model_tuning/          # 代码（已有项目）
├── ev-data/          # 数据（make_data_repo.sh 导出）
└── ev-models/        # 本地权重暂存（上传 ModelScope 后可删）
    ├── ev-v3/lora_adapter/
    └── ev-v4/lora_adapter/
```

好处：三个仓互相之间用 **相对路径 + 版本号** 引用，任何机器 clone 下来都能跑。

## 建仓

```bash
# ① 代码仓
cd /mnt/e/VMOS_workspace/model_tuning
git init -b main
git add -A && git commit -m "feat: E.V. 语音助手 + 三版 LoRA 迭代"
git remote add origin git@github.com:fanta079/model_tuning.git
git push -u origin main

# ② 数据仓（自动导出）
bash make_data_repo.sh --out ~/repos/ev-data
cd ~/repos/ev-data
git init -b main && git add -A && git commit -m "data: v4 (1080 条)"
git remote add origin git@github.com:fanta079/ev-data.git    # 私有！
git push -u origin main

# ③ 权重仓（ModelScope）
pip install modelscope -i https://mirrors.aliyun.com/pypi/simple/
modelscope login --token <你的 token>
modelscope upload <你的账号>/ev-v4 ~/ft_outputs/ev-v4/lora_adapter
```

## 版本绑定：同一个 tag

三个仓都用**同一个 tag 名**（`v3` / `v4`），一眼能对上：

```bash
(cd ev-code && git tag v4 && git push --tags)
(cd ev-data && git tag v4 && git push --tags)
modelscope upload <你>/ev-v4 ... # 模型名自带版本
```

数据仓的 `README.md` 会自动写入**生成这批数据时的代码 commit sha**。
出问题时能回答"这版数据是用哪份人设卡生成的"。

## 换机器怎么恢复

```bash
git clone git@github.com:fanta079/model_tuning.git
git clone git@github.com:fanta079/ev-data.git
python -m venv ~/venvs/ft && source ~/venvs/ft/bin/activate
pip install -r requirements.txt        # 或按 docs 手装
bash setup_models.sh                   # 下底座模型
modelscope download <你>/ev-v4 --local_dir ~/ft_outputs/ev-v4/lora_adapter
bash start_ev.sh --adapter ~/ft_outputs/ev-v4/lora_adapter
```

## 训练时怎么跨仓引用

训练脚本只认 `DATA_PATH`，所以数据在哪个仓都行：

```bash
# 数据在数据仓，训练在代码仓，一条命令连起来
cd ~/repos/ev-code
DATA_PATH=~/repos/ev-data/data/ev4/train.json \
DATA_FORMAT=chat RESPONSES_ONLY=1 NUM_EPOCHS=3 \
OUTPUT_DIR=~/ft_outputs/ev-v4 python train_lora.py
```

> `prepare_data.py` 产出的 `train.json / val.json` 属于**中间产物**，
> 建议只把 `ev4_all.json`（原始合并集）放数据仓，训练时现场划分 —— 划分逻辑变了也能复现。

## 哪些东西**永远**不入库

| 文件 | 原因 |
|---|---|
| `.env` / API key | 泄露即被盗刷 |
| `models/`（底座权重 8GB）| 各仓都放不下，用 `download_model.sh` 重新拉 |
| `~/ft_outputs/*/checkpoint-*` | 157MB/版，只用于中断续训 |
| `app/voice_samples/` | 可重新生成 |
| `logs/` | 运行时输出 |
| `unsloth_compiled_cache/` | 首次运行自动重建 |

## 实际仓库（2026-10-17 已建）

| 仓 | 地址 | 可见性 | 内容 |
|---|---|---|---|
| 代码 | https://github.com/fanta079/model_tuning | **PUBLIC** | 脚本、人设卡、`app/`、`docs/` |
| 数据 | https://github.com/fanta079/ev-data | **PRIVATE** | `data/`（9 个 json）+ `reports/` |
| 权重清单 | https://github.com/fanta079/ev-models | **PRIVATE** | 只有 `MANIFEST.md`（sha256）+ 每版 README |

三仓都打了 **`v4`** tag，权重本体等上传 ModelScope 后再补下載命令。

> 权重仓**故意不存权重**：100MB/版会吃满 GitHub LFS 的 1GB 免费额度。
> 仓库里只留 sha256，用来校验「手上这个 adapter 到底是哪一版」。
